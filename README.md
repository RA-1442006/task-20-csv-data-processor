# CSV Data Processor

A lightweight Python project that reads raw sales and employee data from a CSV file, cleans messy records, and computes summary statistics such as total revenue, top-selling items, average salary, and department counts.

I built this project as a practical internship task to get hands-on experience parsing CSV files and writing reliable data-cleaning logic in Python without relying on heavy third-party libraries like pandas.

---

## What It Does

1. **Loads CSV Data**: Reads rows from `data/sales_data.csv` using Python's standard `csv.DictReader`.
2. **Validates & Cleans Records**: Inspects each row for missing values, negative amounts, or invalid text in numeric columns (such as `"N/A"` or `"abc"`).
3. **Calculates Key Metrics**:
   - Total sales revenue (`units_sold * unit_price`)
   - Total units sold
   - Average employee salary
   - Top-selling product by total volume
   - Best and lowest revenue-generating transactions
   - Record counts per department and geographic region
4. **Tracks Data Quality**: Keeps count of how many rows were skipped and logs which fields caused validation issues.
5. **Generates Reports**: Prints an aligned summary report to the terminal and automatically saves it to `output/summary_report.txt`.

## How Missing and Invalid Values Are Handled

Real-world datasets often have dirty or incomplete rows. In `processor.py`, I wrote a helper function called `to_number` that safely converts strings to integers or floats:

1. **Whitespace & Empty Strings**: Strips surrounding whitespace. If the field is blank or `None`, it returns `None`.
2. **Text in Numeric Fields**: If someone entered `"N/A"`, `"abc"`, or typos, Python's `int()` or `float()` raises a `ValueError`. The helper catches this and returns `None` instead of crashing the program.
3. **Negative Values**: In sales data, negative units sold, unit prices, or salaries are invalid, so any value `< 0` also returns `None`.
4. **Row Skipping & Issue Logging**: When a row contains a `None` in any of its essential numeric columns, the row is skipped from the calculations, and the specific column name is tallied in a dictionary (`field_issues`). This ensures our averages and totals are not skewed by corrupted data, while giving visibility into why rows were dropped.

## Conceptual Questions & Answers

### 1. What is CSV?
CSV stands for "Comma-Separated Values". It is a plain-text file format used to store tabular data (rows and columns). Each line in the file represents a data record, and each field in that record is separated by a comma (or sometimes another delimiter like a semicolon or tab). Because it is simple text, it can be opened by text editors, spreadsheet software (like Excel or Google Sheets), and processed easily in programming languages.

### 2. How can Python read CSV files?
Python includes a built-in `csv` module in its standard library:
- **`csv.reader`**: Reads the CSV file row by row as lists of strings (e.g. `row[0]`, `row[1]`).
- **`csv.DictReader`**: Reads each row as a dictionary where the dictionary keys are taken from the header row (e.g. `row["units_sold"]`). This is much less prone to index errors when column order shifts.

### 3. How would you handle missing values in a CSV?
How you handle missing data depends on the goal:
- **Row Dropping**: If critical columns (like price or primary key) are missing, dropping the row is often the safest choice to avoid calculating wrong figures.
- **Default / Imputation**: For minor or non-critical fields, you can replace missing values with sensible defaults (like `0` for counts, `"Unknown"` for missing text categories, or the column average/median).
- **Flagging & Logging**: Always count and report missing rows (as done in this project) so whoever uses the report knows data was missing and can address data collection upstream.
